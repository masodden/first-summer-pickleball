# FIRST SUMMER PICKLEBALL

Приложение для проведения локальных турниров по пиклболу: регистрация игроков, приём оплаты,
счёт на кортах в прямом эфире и турнирная таблица с медалями. Работает как Telegram Mini App и
как обычный сайт — смотреть турнир можно без входа.

- **Форматы:** individual americano (каждый играет в паре с каждым) и mexicano (пары собираются
  по текущей таблице).
- **Роли:** администратор, модератор, авторизованный игрок, наблюдатель без входа.
- **Живые обновления:** организатор ставит галочку на своём телефоне — второй телефон и табло у
  корта видят это сразу.
- **Языки:** русский по умолчанию, английский переключается в настройках.

## Что нужно перед началом

Для локального запуска: [Docker Desktop](https://www.docker.com/products/docker-desktop/) —
и больше ничего.

Для деплоя: VPS с Ubuntu 24.04 (хватит 1 CPU / 2 ГБ RAM), домен и аккаунт Telegram.

Про DUPR: приложение **не обращается** к API DUPR — партнёрский доступ выдаётся только клубам с
договором. Поэтому DUPR ID и парный рейтинг вводятся вручную: игрок указывает свой ID при первом
входе, организатор подтверждает его при приёме на турнир, а рейтинг можно поправить в один тап
прямо в списке участников. Личность игрока подтверждает Telegram, а не DUPR.

## Быстрый запуск на своём компьютере

```bash
git clone https://github.com/<ваш-аккаунт>/first-summer-pickleball.git
cd first-summer-pickleball
pnpm docker:dev
```

Настраивать ничего не нужно: локальный компоуз поднимает базу, применяет миграции, добавляет
24 демо-игрока и запускает API с фронтендом. Через 2–4 минуты (первый раз качаются образы)
откройте:

- приложение — <http://localhost:4200>
- API — <http://localhost:3000/api/tournaments>

В локальном режиме включён вход без Telegram: «Настройки» → кнопка входа, и вы администратор.
Код администратора для локального запуска — `first-summer-admin`. Такой вход работает только на
`localhost` при `ALLOW_DEV_LOGIN=true`; в продакшене он запрещён на уровне кода.

Остановить: `pnpm docker:dev:down`.

### Запуск без Docker

Нужны Node.js 22 или 24 и pnpm 11, плюс PostgreSQL 17 (можно поднять только базу через Docker).

```bash
pnpm install
docker run -d --name fsp-db -e POSTGRES_USER=fsp -e POSTGRES_PASSWORD=fsp \
  -e POSTGRES_DB=fsp -p 5432:5432 postgres:17-alpine

# .env: DATABASE_URL=postgres://fsp:fsp@localhost:5432/fsp
#       JWT_SECRET=любая-строка-от-16-символов
#       ALLOW_DEV_LOGIN=true

pnpm --filter @fsp/shared build
pnpm --filter @fsp/engine build
pnpm db:migrate
pnpm db:seed -- --demo     # 24 демо-игрока, чтобы было с кем создавать турнир

# дальше удобнее `pnpm dev`: shared/engine в watch, API и web рядом.
# В angular.json @fsp/shared исключён из Vite prebundle — новые ключи i18n
# подхватываются без перезапуска после пересборки shared.
pnpm dev                   # API на 3000, фронтенд на 4200
```

Полезные команды:

| Команда             | Что делает                                                    |
| ------------------- | ------------------------------------------------------------- |
| `pnpm test`         | юнит-тесты движка турнира (расписание, пары, таблица)         |
| `pnpm typecheck`    | проверка типов во всех пакетах                                |
| `pnpm build`        | production-сборка всего                                       |
| `pnpm e2e:scenario` | сквозной прогон целевого сценария по живому API               |
| `pnpm lint`         | проверка форматирования (Prettier), `pnpm format` — исправить |

Сквозной сценарий проигрывает по запущенному API целый вечер: два параллельных турнира 12 + 12 на
шести кортах, 11 раундов americano с проверкой, что каждый сыграл в паре с каждым ровно один раз,
mexicano с раундами по ходу игры, права ролей, конфликт версий при правке счёта с двух устройств и
обновления по WebSocket — 51 проверка. Запускать можно сколько угодно раз, данные прогонов не
пересекаются:

```bash
pnpm docker:dev                                        # в одном терминале
E2E_BASE_URL=http://localhost:3000 pnpm e2e:scenario   # в другом
```

| **Свой VPS** (Timeweb, Selectel, Hetzner, Aeza) | 200–600 ₽/мес    | всё в одном месте, полный контроль, дёшево | обновления и бэкапы на вас                |
| Railway / Render                                | от $5/мес + база | деплой из git, база в комплекте            | дороже, база в бесплатном тарифе засыпает |

(Финляндия/Германия), чтобы пинг от телефонов на площадке был небольшим.

## Деплой на VPS с нуля

### 1. Домен

Купите домен (reg.ru, nic.ru, Cloudflare) — например `pickleball.example.com`.
Telegram Mini App работает **только по HTTPS**, а сертификат выдаётся на домен, поэтому без
домена бота не будет. Табло по IP-адресу открыть можно, Mini App — нет.

В панели регистратора добавьте A-запись:

```
Тип: A    Имя: pickleball (или @ для корня)    Значение: IP вашего VPS    TTL: 3600
```

Проверьте, что запись разошлась (может занять до часа):

```bash
dig +short pickleball.example.com
```

Должен вывестись IP вашего сервера.

### 2. Подготовка сервера

Подключитесь по SSH (`ssh root@IP-сервера`) и выполните:

```bash
# Обновляем систему
apt update && apt upgrade -y

# Ставим Docker одной командой
curl -fsSL https://get.docker.com | sh

# Отдельный пользователь вместо root — так безопаснее
adduser --disabled-password --gecos "" fsp
usermod -aG docker fsp

# Firewall: оставляем только SSH и веб
apt install -y ufw
ufw allow OpenSSH && ufw allow 80 && ufw allow 443
ufw --force enable
```

Дальше работаем под пользователем `fsp`: `su - fsp`.

### 3. Забираем код и заполняем конфигурацию

```bash
git clone https://github.com/<ваш-аккаунт>/first-summer-pickleball.git
cd first-summer-pickleball
cp .env.example .env
```

Сгенерируйте секреты (каждая команда печатает строку, которую нужно вставить в `.env`):

```bash
openssl rand -hex 24   # → POSTGRES_PASSWORD
openssl rand -hex 32   # → JWT_SECRET
openssl rand -hex 16   # → TELEGRAM_WEBHOOK_SECRET
```

Откройте `.env` (`nano .env`) и заполните:

```ini
APP_DOMAIN=pickleball.example.com
POSTGRES_PASSWORD=<из первой команды>
JWT_SECRET=<из второй команды>
BOOTSTRAP_ADMIN_CODE=<придумайте свой код, минимум 6 символов>
TELEGRAM_BOT_TOKEN=<получим на следующем шаге>
TELEGRAM_BOT_USERNAME=<имя бота без @>
TELEGRAM_WEBHOOK_SECRET=<из третьей команды>
```

`BOOTSTRAP_ADMIN_CODE` — это код, которым вы подтвердите, что вы действительно администратор
клуба при первом входе. Никому его не показывайте.

### 4. Запуск

```bash
pnpm docker:prod
# или без pnpm на сервере (важно: --env-file .env — иначе Compose
# ищет переменные рядом с infra/docker-compose.yml и не видит корневой .env):
docker compose --env-file .env -f infra/docker-compose.yml up -d --build
```

Первая сборка занимает 5–10 минут. Что происходит: собираются образы API и фронтенда,
поднимается PostgreSQL, применяются миграции, Caddy получает сертификат Let's Encrypt
и включает HTTPS. База сначала пустая — игроков импортируете сами.

Проверьте:

```bash
docker compose --env-file .env -f infra/docker-compose.yml ps        # все сервисы healthy/running
docker compose --env-file .env -f infra/docker-compose.yml logs -f api
curl https://pickleball.example.com/api/tournaments  # должен вернуть {"items":[],"total":0}
```

Откройте `https://pickleball.example.com` в браузере — увидите пустой список турниров в режиме
наблюдателя.

## Telegram-бот и Mini App

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username
   (например `FirstSummerPickleballBot`).
2. Скопируйте токен и положите его в `.env` (`TELEGRAM_BOT_TOKEN`), а username — в
   `TELEGRAM_BOT_USERNAME` (без `@`).
3. Там же у BotFather: `/setmenubutton` → выберите бота → пришлите
   `https://pickleball.example.com` и подпись кнопки, например «Турниры».
4. Перезапустите приложение, чтобы бот увидел токен:

```bash
docker compose --env-file .env -f infra/docker-compose.yml up -d
```

5. Проверьте вебхук:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

В ответе должен быть ваш адрес и `"pending_update_count": 0`. Приложение регистрирует вебхук само
при старте, если задан `TELEGRAM_WEBHOOK_SECRET`. Если секрет пустой, бот работает опросом
(long polling) — годится для локальной разработки, для сервера лучше вебхук.

6. Откройте бота в Telegram, нажмите кнопку меню — приложение откроется внутри мессенджера, вход
   произойдёт автоматически по подписи Telegram.

Что умеет бот: открывает Mini App, обрабатывает ссылки-приглашения (`/start invite_...`) и
присылает уведомления о старте турнира, готовности корта и результатах. Уведомления
отключаются в настройках приложения.

## Первый вход администраторов

Роль клуба хранится на карточке игрока (**DUPR ID**), а не на Telegram. При входе
аккаунт подхватывает роль с привязанной карточки.

Два DUPR ID по умолчанию всегда администраторы и их нельзя понизить: **PZQZKM** и
**P5ML0M**. Остальным роль (игрок / модератор / администратор) можно выдать из
карточки игрока — Telegram для этого не нужен.

1. Импортируйте справочник DUPR (или создайте карточку).
2. Откройте Mini App в Telegram и привяжите свой DUPR (для PZQZKM / P5ML0M).
3. В проде появится поле «Код администратора» — `BOOTSTRAP_ADMIN_CODE` из `.env`.

Локально (`ALLOW_DEV_LOGIN=true`) код не спрашивается. В списке «Админ» → «Аккаунты»
видны только администраторы и модераторы; после понижения до игрока строка пропадает.

Остальные игроки заходят так: открывают Mini App, вводят свой DUPR ID, и заявка попадает
организатору («Администрирование» → «Заявки на привязку»). Организатор подтверждает её, когда
видит человека на площадке. Альтернатива без ожидания: в карточке игрока создайте
ссылку-приглашение и отправьте её в личку — по ней Telegram привяжется к карточке сразу.

## Игроки: импорт и ручное добавление

Есть три способа наполнить базу.

**1. Выгрузка справочника DUPR.** «Администрирование» → «Импорт игроков» → выберите файл.
Понимаются CSV, JSON и формат `players.js` из русского списка
[bilinaspol.github.io/dupru](https://bilinaspol.github.io/dupru/) (файл со сжатыми данными
внутри). Имя берётся из колонки Player's Name (как в DUPR), не из русского перевода.
Сопоставление идёт по DUPR ID, поэтому повторный импорт не создаёт дубликатов.

Ручные правки рейтинга при импорте не затираются: если в выгрузке другое значение, оно
показывается в карточке игрока как расхождение, и вы решаете, какое оставить.

Из командной строки то же самое — файлом или прямо по ссылке:

```bash
docker compose -f infra/docker-compose.yml exec api \
  node apps/api/dist/db/import-directory.js --url https://bilinaspol.github.io/dupru/players.js

# локально, без Docker
pnpm db:import -- --file ./players.csv
```

**2. Вручную по одному.** «Игроки» → «Создать карточку»: имя, фамилия, DUPR ID и рейтинг.
DUPR ID можно не указывать — получится гостевая карточка. Когда игрок узнает свой ID, в его
карточке нажмите «Указать DUPR ID»: карточки объединятся вместе со всей статистикой.

**3. Сам игрок.** Заходит через Telegram, указывает свой DUPR ID и рейтинг — карточка создаётся
автоматически, вам остаётся подтвердить заявку.

## Как вести турнир

Сценарий обычного вечера с двумя категориями (12 + 12 человек, 6 кортов):

1. **Создайте два турнира** — «Турниры» → «Создать турнир». Для каждого: формат Americano,
   12 игроков, 3 корта, максимальный счёт 11, 11 игр, время матча по желанию. Категории назовите
   `advanced` и `intermediate` — на экране турнира появится переключатель между ними, и вести их
   можно как с одного телефона, так и с двух разных.

   Под количеством кортов есть поля «Названия кортов». Если вечер занимает корты 4, 5 и 6, впишите
   их номера — именно они будут стоять рядом с матчами, в CSV и на публичном табло. Подойдёт и
   название вроде «Центральный». Незаполненные поля означают обычную нумерацию с единицы.
   Порядок в списке — это уровень корта: в mexicano на первом играют лидеры таблицы, поэтому
   ставьте главный корт первым. В americano приложение само разводит игроков по разным кортам,
   чтобы за вечер каждый сыграл на всех и никто не остался на одном и том же.

2. **Соберите состав.** Добавляйте игроков из базы («Добавить игрока» → поиск) или ждите, пока
   заявятся сами — список у вас на экране обновляется мгновенно, обновлять страницу не нужно.
   Когда мест не осталось, следующие попадают в лист ожидания, откуда их можно перевести
   в состав одной кнопкой.
3. **Примите участников.** Напротив каждого — галочка «подтверждён и оплатил». Рейтинг DUPR
   правится прямо в строке, заходить в профиль не нужно. Сверху видно «Подтверждено 11 из 12».
4. **Создайте игры.** Когда все галочки стоят, загорается кнопка «Создать турнир и начать».
   Для americano все 11 раундов создаются сразу — можно листать их вперёд и смотреть, кто с кем
   играет. Пары до начала первого матча можно перемешать («Перемешать игроков») — рейтинги
   учитываются, чтобы силы на кортах были примерно равны.
5. **Ведите матчи.** На экране «Корты» видны все корты раунда одновременно. Раунд стартует одной
   кнопкой «Начать раунд»: на площадке свисток один на все корты, и таймер тоже общий. «Пауза»
   останавливает раунд целиком, «Завершить раунд» — тоже, и только вручную, даже если время вышло.
   Пока раунд идёт, счёт в матчах не вводится. После «Завершить раунд» под каждым кортом
   появляются пресеты 11:9 / 11:8 / 11:7 (и зеркально), кнопки ±1 и «Сохранить счёт».
6. **Смотрите таблицу** в любой момент — она обновляется в прямом эфире. Сортировка по умолчанию
   та, что выбрана при создании турнира; любой столбец можно сделать главным одним касанием, а
   повторное касание переворачивает порядок (стрелка показывает направление).
7. **Завершите турнир,** когда все игры сыграны. До завершения любой счёт можно исправить, после
   — нет. Первым трём местам присваиваются медали, результаты выгружаются в CSV, а публичной
   ссылкой на табло можно поделиться в чате клуба.

Для mexicano всё то же, только раунды создаются по мере игры: сыграли — нажали «Создать
следующий раунд», и пары собрались по текущей таблице (лидеры на первый корт). Количество игр
можно не задавать вовсе и остановить турнир в любой момент.

Наблюдатели и игроки могут ходить по всем раундам и смотреть табло без входа — действия
организатора на текущем матче при этом не сбрасываются.

## Бэкапы

Ручная копия:

```bash
cd ~/first-summer-pickleball
sh infra/backup.sh          # положит дамп в infra/backups/fsp-ГГГГ-ММ-ДД_ЧЧ-ММ.sql.gz
```

Каждую ночь автоматически (`crontab -e`):

```
0 4 * * * cd /home/fsp/first-summer-pickleball && sh infra/backup.sh >> /home/fsp/fsp-backup.log 2>&1
```

Копии старше 14 дней удаляются сами (меняется переменной `KEEP_DAYS`). Раз в месяц скачивайте
свежий дамп к себе: `scp fsp@IP:~/first-summer-pickleball/infra/backups/*.gz .`

## Типичные ошибки

**Сайт не открывается, в логах Caddy ошибки сертификата.** DNS ещё не разошёлся или A-запись
указывает не туда. Проверьте `dig +short ваш-домен` и что порты 80 и 443 открыты в firewall и в
панели хостера.

**Mini App открывается, но вход не происходит.** Не задан `TELEGRAM_BOT_TOKEN` либо приложение не
перезапущено после его добавления. Проверьте `docker compose logs api | grep -i telegram`.

**«На сервере не задан TELEGRAM_BOT_TOKEN».** То же самое: добавьте токен в `.env` и выполните
`docker compose --env-file .env -f infra/docker-compose.yml up -d`.

**Бот не отвечает на `/start`.** Посмотрите `getWebhookInfo` (см. раздел про бота). Если там
`last_error_message`, значит Telegram не может достучаться до домена — обычно это HTTPS или
firewall.

**«Неверный код администратора».** `BOOTSTRAP_ADMIN_CODE` в `.env` не совпадает с введённым.
После изменения `.env` контейнер нужно перезапустить. Локально код не спрашивается вовсе —
если он всё же требуется, значит `ALLOW_DEV_LOGIN` выключен.

**«Сначала подтвердите всех участников».** Кнопка старта загорается только когда у всех стоит
галочка оплаты. Лишних участников можно убрать из состава.

**«Данные изменились с другого устройства».** Двое организаторов правили один матч одновременно.
Приложение подтянет актуальный счёт — введите свой заново, ничего не потеряется.

**Порт 5432 занят при локальном запуске.** У вас уже работает PostgreSQL. Либо остановите его,
либо поменяйте порт в `infra/docker-compose.dev.yml`.

**Кончилось место на диске.** `docker system prune -a` уберёт старые образы, но сначала
проверьте, что бэкапы вы уже скачали.

## Как всё устроено внутри

```
apps/
  web/       Angular 22 — сигналы, zoneless, lazy-маршруты, liquid glass
  api/       Fastify 5 — REST, WebSocket, Telegram-бот на grammY
packages/
  engine/    расписание americano и mexicano, пары по рейтингу, таблица (юнит-тесты)
  shared/    типы, схемы валидации, коды ошибок, словари ru/en — общие для фронта и бэка
infra/       Dockerfile'ы, docker-compose для локали и продакшена, Caddy, скрипт бэкапа
scripts/     сквозной прогон целевого сценария по живому API
```

Ключевые решения:

- **Ключ игрока — DUPR ID.** Гостевые карточки живут в том же пространстве ключей с префиксом
  `G-` и позже сливаются с настоящими.
- **Telegram подтверждает личность, DUPR ID подтверждает организатор.** Без партнёрского доступа
  к DUPR это единственный честный способ не пустить чужого под вашим ID.
- **Счёт защищён версией.** Каждое изменение матча несёт номер версии: если параллельно правили
  с двух телефонов, второй запрос получит `conflict_version` вместо тихой перезаписи.
- **Таймеры серверные.** Клиент считает время от `startedAt`, полученного с сервера, поэтому на
  всех устройствах он одинаковый и не сбивается от перезагрузки страницы.
- **Незавершённые действия не теряются.** Если сеть пропала, изменяющие запросы складываются в
  очередь, в шапке появляется счётчик, и при возврате связи всё уходит на сервер.

### Переменные окружения

| Переменная                                   | Обязательна | Назначение                                        |
| -------------------------------------------- | ----------- | ------------------------------------------------- |
| `APP_DOMAIN`                                 | да (прод)   | домен без `https://`, нужен Caddy и ссылкам       |
| `POSTGRES_PASSWORD`                          | да (прод)   | пароль базы                                       |
| `JWT_SECRET`                                 | да          | подпись токенов сессии, минимум 16 символов       |
| `BOOTSTRAP_ADMIN_CODE`                       | да (прод)   | код первого входа администраторов клуба           |
| `TELEGRAM_BOT_TOKEN`                         | для бота    | токен из BotFather                                |
| `TELEGRAM_BOT_USERNAME`                      | для бота    | username бота без `@`, нужен ссылкам-приглашениям |
| `TELEGRAM_WEBHOOK_SECRET`                    | нет         | если задан — вебхук, если пуст — long polling     |
| `DATABASE_URL`                               | локально    | строка подключения к PostgreSQL                   |
| `ALLOW_DEV_LOGIN`                            | нет         | вход без Telegram; в продакшене запрещён          |
| `PUBLIC_WEB_URL`, `CORS_ORIGIN`, `LOG_LEVEL` | нет         | подставляются автоматически из `APP_DOMAIN`       |
